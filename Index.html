What is Git?


Git is a version control system. It runs on your computer and records snapshots of your project each time you save a checkpoint, called a commit. You can go back to any earlier snapshot, compare versions, and work on new ideas in separate branches without breaking the working code.


Git works fully offline. Everything lives in a hidden .git folder inside your project. That folder is your local repository.


Key terms




TermMeaning


Repository (repo)A project folder tracked by Git, including its full history.


CommitA saved snapshot with a message describing the change.


BranchAn independent line of work. The default is usually main.


RemoteA copy of the repo hosted elsewhere, such as on GitHub.


Push / PullSend your commits to the remote / fetch commits from the remote.


CloneDownload a full copy of a remote repo to your machine.









What is GitHub?


GitHub is a website that hosts Git repositories in the cloud. It gives your local repo a shared home so teammates can see your work, review it, and build on it. It also adds tools around Git: pull requests, issues, access control, and automation with GitHub Actions.




Git
The tool. Tracks changes on your machine. Works offline. Free and open source.


GitHub
The service. Hosts repos online, enables collaboration, and connects to deployment pipelines.




Other services such as GitLab and Bitbucket do the same job. The Git commands you learn here work with all of them.


Why it matters for cloud administration


Infrastructure scripts, configuration files, and application code all live in repositories. Cloud platforms deploy from them, often automatically when new code reaches the main branch. Pushing to GitHub is the first step of most deployment pipelines.

  1. Create the local repository
    

    Open a terminal in your project folder and initialise Git.
    

    cd my-project
git init
git branch -M main
    2. 


  2. Check what Git sees
    

    New files show as untracked.
    

    git status
    3. 


  3. Stage your files
    

    Staging picks which changes go into the next commit. Add a .gitignore file first to keep secrets and clutter (like .env or node_modules/) out of the repo.
    

    git add .          # stage everything
git add app.py    # or stage one file
    4. 


  4. Commit
    

    Save the snapshot with a clear message.
    

    git commit -m "Add initial project files"
    5. 


  5. Create an empty repository on GitHub
    

    On github.com, click New repository, name it, and leave "Add a README" unticked so it starts empty. Copy the repository URL shown on the next page.
    6. 


  6. Connect local to remote
    

    The name origin is the standard label for your main remote.
    

    git remote add origin https://github.com/YOUR-USERNAME/my-project.git
git remote -v     # verify
    7. 


  7. Push
    

    The -u flag links your local main to the remote one, so later you can type just git push.
    

    git push -u origin main
    

    Refresh the GitHub page. Your files and commit history are now online.
    8. 



Never commit passwords, API keys, or cloud credentials. Once pushed, treat a leaked secret as compromised and rotate it, even if you delete the file later.







The daily cycle


After the first push, your routine repeats:


git pull                       # get teammates' latest changes
# ...edit files...
git status                     # review what changed
git add .
git commit -m "Fix login timeout"
git push


Starting from an existing GitHub repo instead


git clone https://github.com/USER/REPO.git


Working on a branch


git switch -c feature/new-page   # create and move to a branch
git push -u origin feature/new-page
# then open a Pull Request on GitHub to merge into main


Deploying from GitHub


Once code is on GitHub, a cloud service can pull it and run it. Typical options include GitHub Pages for static sites, Azure App Service or AWS Amplify connected to a repository, and GitHub Actions pipelines that build and deploy on every push to main. The service you pick depends on what the class is using.







Common errors




MessageCause and fix


fatal: not a git repositoryYou are outside the project folder, or skipped git init.


remote origin already existsChange it with git remote set-url origin NEW-URL.


Authentication failedUse a personal access token instead of your password, or set up SSH.


rejected ... fetch firstThe remote has commits you lack. Run git pull, then push again.


nothing to commitYou have not changed or staged anything. Check git status.
